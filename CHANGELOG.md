# Changelog

## 0.2.1

- Removed blanket work-contract approval tasks from the user's inbox.
- AI requests now start automatically and only concrete decisions are assigned to the user.
- Added decision-specific task titles for Git initialization, dependencies, secrets, network, and scope changes.
- Added a user-inbox location question when a new project is requested from a protected home directory.

## 0.2.0

- Added one due-date and priority ordered task list shared by the user and AI.
- Added `add`, `inbox`, `show`, `answer`, and queue-oriented `work` commands.
- Added automatic contract questions in the user's inbox and answer-driven AI resume.
- Added persistent work-item REST endpoints for future local GUI clients.
- Reframed the product as a minimal work coordinator while retaining the safe development executor.
- Added an Execution Policy-safe Windows installer.

## 0.1.0

- Added contract-first Ollama planning and tool execution.
- Added SQLite event ledger, resumable tool results, and approval-based memories.
- Added secret, scope, command, and Git worktree safety boundaries.
- Added Ink TUI, Windows CLI commands, and authenticated localhost REST/SSE API.
- Added fixture-based Git, API, policy, persistence, and Ollama streaming tests.
